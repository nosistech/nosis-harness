### high-1 · [nh-core / correctness] Compaction cost guard defers compaction until input exceeds the working context limit
- **Location:** `crates/nh-core/src/lib.rs:1821-1840`
- **Why:** compact_history picks the EARLIEST user index whose retained suffix fits under target (COMPACT_TARGET=0.50 of limit), i.e. the candidate that retains the MOST (retained ~= just under 50% of limit). Then the guard `if tokens <= retained_tokens { return None; }` (line 1838) requires elided > retained. At the trigger threshold (COMPACT_AT=0.70), elided ~= input - retained ~= 20% of limit while retained ~= 50%, so the guard returns None on essentially every trigger. Because retained stays pinned near 50% as history grows, elided only exceeds retained when input > ~100% of the working limit — so for any route whose real context equals the working window (e.g. 128k routes), the provider rejects the request with a context-length error before compaction ever fires, and for clamped 1M routes the 70% trigger and the context-rot guard are both silently defeated. The guard also never falls back to a LATER candidate (smaller retained, larger elided) that would both pass the cost check and meet the target. The unit test only covers the big-old-turns/small-recent-turns shape where the guard happens to pass.
- **Fix:** Fold the cost check into candidate selection: iterate user_indices and pick the first index that satisfies BOTH retained <= target AND elided > retained (or drop the guard entirely when input >= COMPACT_AT * limit, since avoiding a hard context-overflow beats a one-time cache re-prefill). Add a test at limit-realistic proportions (input=70% of limit, many uniform turns) asserting compaction fires.
- **Verifier:** Verified at crates/nh-core/src/lib.rs:1821-1840. Candidate selection (lines 1821-1828) iterates user_indices in ascending order and takes the FIRST index whose retained suffix fits under target=0.50*limit, so retained is pinned just under 50% of the working limit. The guard at line 1838 (`if tokens <= retained_tokens { return None; }`) then requires elided > retained. At the 0.70 trigger (line 1588), elided ≈ 20% vs retained ≈ 50% for uniform-turn histories, so compact_history returns None on essentially every trigger; elided only exceeds retained once input ≈ 100% of the working limit. effective_context (line 1482) = min(window, 256k), so for any route ≤ 256k the working limit IS the real provider window — the request overflows and the run hard-fails via the Err path at lines 1611-1625 (no overflow retry/recovery exists anywhere in the file) before compaction ever fires. The unwrap_or(required_start) fallback is equally defeated (retained > 50%, elided < 20%), and no later candidate is ever tried. The only unit test (lines 1897-1935, limit=100, huge old turns + tiny recent turns) covers exactly the one shape where the guard passes. Reachable on the main non-test path (run_with_history turn loop whenever context_limit is set). High severity stands: compaction is effectively dead in the common uniform-turn case and long sessions on ≤256k routes terminate with a provider context error.

### high-4 · [nh-tools / correctness] Windows exec quoting mangles any approved command containing double quotes (cmd /C via Command::args)
- **Location:** `crates/nh-tools/src/lib.rs:364-372`
- **Why:** ExecShell builds Command::new("cmd").args(["/C", command]). Rust's std applies MSVC argv quoting to args: a command containing a space or quote is wrapped in quotes and internal '"' becomes '\"'. cmd.exe does not parse backslash-escaped quotes, so an approved command like git commit -m "two words" reaches cmd as "git commit -m \"two words\"" — cmd strips only the outer quotes and the child sees literal backslash-quote sequences, producing a commit message of \"two (or a parse failure). This is the primary platform (Windows-first product), and it also means the byte string the user approved via ctx.approve is not the byte string executed.
- **Fix:** On Windows use std::os::windows::process::CommandExt::raw_arg: c.arg("/C"); c.raw_arg(command); which passes the approved command to cmd.exe verbatim. Keep sh -c unchanged on Unix.
- **Verifier:** Verified at crates/nh-tools/src/lib.rs:364-372: ExecShell spawns Command::new("cmd").args(["/C", command]). Rust std applies MSVC argv quoting to args (embedded '"' -> '\"', whole arg wrapped in quotes when it contains spaces/quotes); std's cmd-safe quoting only applies to .bat/.cmd spawning, not explicit `cmd` invocation. cmd.exe does not honor backslash-escaped quotes: for `git commit -m "two words"` the line becomes `cmd /C "git commit -m \"two words\""`, cmd strips only the outer quotes, and the child parses `\"` as literal quote chars via CommandLineToArgvW, yielding mangled args ("two / words"). Quote-free commands survive via cmd's strip-outer-quotes fallback, which is why basic usage works and this lurks. Reachable on the shipped non-test path (ExecShell is in builtin_tools(), execute() runs post-approval, cfg!(windows) is the primary platform), and the executed bytes differ from the bytes the user approved via ctx.approve. Proposed raw_arg fix is the standard correct remedy. High severity stands: common commands (quoted commit messages, paths with spaces) silently corrupt on the flagship platform.

### high-5 · [nh-vault / security] Audience broker host parse disagrees with reqwest (backslash bypass): approved for api.deepseek.com, sent to evil host
- **Location:** `crates/nh-vault/src/lib.rs:141-162`
- **Why:** normalized_host() terminates the authority only on '/', '?', '#' (line 147) and then takes the text after the last '@' (line 150). The WHATWG URL parser used by reqwest/url (the actual HTTP client — nh-core/nh-tools depend on reqwest) ALSO terminates the authority of special schemes on '\'. So for base_url = "https://evil.example\@api.deepseek.com/v1": normalized_host sees authority "evil.example\@api.deepseek.com", rsplits on '@' and returns "api.deepseek.com" — which IS in the bundled-law audience for the deepseek entry — while reqwest parses host = "evil.example" (the '\' starts the path) and sends the just-materialized API key there. base_url comes from catalog.toml found in the WORKING repo (cmd_run::find_catalog(&cwd)), i.e. exactly the untrusted source the broker exists to defend against ("an untrusted catalog cannot materialize a credential by redirecting its route", cmd_run.rs:119-120). nh-cli's duplicate host_of() (cmd_run.rs:256-271) has the identical flaw, so the caller does not save you. This defeats the crate's flagship guarantee.
- **Fix:** Treat '\' as an authority terminator: `.split(['/', '\\', '?', '#'])` in normalized_host (and in nh-cli host_of, or better delete host_of — see separate finding). Safer still: parse with the same url crate reqwest uses (url::Url::parse(...).host_str()) so broker and client can never disagree, and refuse when parsing fails. Add a regression test: get_scoped(entry, "https://evil.example\\@api.deepseek.com/v1", ["api.deepseek.com"]) must refuse.
- **Verifier:** Confirmed at cited location. normalized_host (nh-vault/src/lib.rs:147) terminates the authority only on ['/','?','#'] then rsplit('@'), so "https://evil.example\@api.deepseek.com/v1" yields host "api.deepseek.com" — matching the deepseek approved audience and materializing the key. The actual client (nh-core/src/lib.rs:243/276, reqwest .post of "{base_url}/chat/completions") parses via the url crate (WHATWG), which normalizes '\' to '/' for special schemes, terminating the authority at "evil.example" and sending the key there. base_url is copied verbatim from the working-repo catalog (nh-routes/src/lib.rs:259,669) with no backslash validation — exactly the untrusted source the broker (cmd_run.rs:112-120) exists to defend. The duplicate host_of (cmd_run.rs:261) shares the flaw, so the caller offers no backstop. Genuine parser-differential credential-exfil bypass on the production nh run path; high severity justified.

### high-7 · [nh-fleet / concurrency] repair_uncommitted_tail on the read path can truncate bytes a live writer is committing (lost ledger events)
