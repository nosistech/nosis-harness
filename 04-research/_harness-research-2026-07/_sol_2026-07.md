# Nosis Harness improvement research — repository-grounded design pass

**Date:** 2026-07-16  
**Mode:** repository-only research; no network facts were refreshed  
**Decision rule:** THE LAW — small, simple, secure, safe, lightweight, readable, auditable, modular, congruent, harmonic

This report distinguishes repository observations from provider claims. Every current-provider capability, API behavior, price behavior, or availability assertion that should be checked against live first-party documentation is tagged **[VERIFY-LIVE]**. A key tag means the direct-API proposal cannot be exercised with the credentials presently held. Design recommendations do not assume that every advertised provider feature survives verification.

## 1. Executive summary — top 10 improvements, ranked

1. **Bind every vault secret to an approved network audience.** A repository-controlled catalog or MCP config must never be able to select a vault entry and redirect that credential to an arbitrary origin.
2. **Finish the actual “cheapest capable” resolver.** Add a capability request, expected-cost scorer, warm-cache state, and auditable rejection trace to the one RouteResolver instead of resolving only explicit IDs or cheapest output sticker price.
3. **Ship three first-class execution profiles.** `frugal`, `balanced`, and `max-quality` should centrally control route scoring, output caps, reasoning, context pressure, tool exposure, deferral, retries, and provider overrides without ever weakening law or route-required reasoning persistence.
4. **Turn token telemetry into honest money telemetry.** Snapshot the route price at request start, separate cache-hit and cache-miss input, record currency and confidence, reserve worst-case spend before dispatch, and show actual/maximum cost in the HUD and receipts.
5. **Put a bounded envelope around every tool result.** Large files, command logs, MCP schema bombs, and repeated output should become a short inline excerpt plus an auditable handle and digest; this saves tokens and closes a denial-of-wallet/prompt-injection surface.
6. **Replace one-stage history deletion with a five-stage context engine.** Preserve a byte-stable prompt frame, then apply budget reduction, snip, microcompact, context collapse, and auto-compact with explicit protected anchors and compaction receipts.
7. **Add read/egress policy and provenance-taint gating.** Secret-bearing paths need read controls, and any mutation causally downstream of external/MCP content should require explicit approval even when the target path is normally auto-approved.
8. **Make approvals full-fidelity and sandbox the approved action.** Never ask a user to approve truncated content; cap or expand long actions, show exact effects, then execute inside an environment allowlist, timeout, process-tree limit, and the strongest honest Windows containment available.
9. **Broaden the normalized request contract before adding providers.** Output caps, structured response contracts, multimodal content parts, tool-selection policy, stream assembly, and reasoning blocks belong in the two wire adapters, guarded by catalog capabilities.
10. **Replace milestone claims with an evidence matrix.** Each differentiator should have mock, live, security, cost, UX, and Windows evidence; provider facts should carry verification timestamps and expiry just as prices already do.

## 2. Lens A — providers for which keys exist

### A1. Make cacheability a measurable contract, not an emergent property

**Design sketch.** The repository already parses cached-token usage and preserves the first system message, but the invariant is narrower than the provider cache key: message ordering, tool ordering/schema bytes, route, wire, and profile can also affect prefix reuse. Add a pure `PromptFrame`/`CacheEpoch` layer under `crates/nh-core/src/context.rs` with four stable regions: immutable identity/law, stable tool schemas, epoch summary, and dynamic recent history. Canonically sort tool specs by qualified name and canonicalize JSON Schema object keys. Hash the route ID, wire, immutable prompt bytes, tool-schema bytes, and cache-affecting profile fields. A change creates a new epoch with a typed reason; it never silently edits the old prefix. Extend receipts with `cache_epoch`, `prefix_digest`, `tool_digest`, `cached_tokens`, and `cache_reset_reason`. Optional cache mechanics such as minimum cacheable prefix, TTL, automatic versus explicit cache blocks, and cache-write price remain route data in `catalog.toml` **[VERIFY-LIVE]**.

**Smallest MVP.** Sort/canonicalize tool specs, calculate two digests, reset per-route cache telemetry on route/profile changes, and show `warm`, `cold`, or `unknown`; do not add a provider-specific cache API until a live request proves it is needed.

**THE LAW fit.** Strongly auditable, congruent, and cost-saving. The tension is extra metadata; keep it to one compact struct and hashes rather than storing prompts.

**Judgment.** In scope. **Value: High. Effort: M.** Provider cache semantics and fields **[VERIFY-LIVE]**.

### A2. Add a normalized request policy with hard output control

**Design sketch.** `ChatRequest` currently has messages, tools, and thinking effort; the OpenAI wire sends no output cap, while the Anthropic wire applies a fixed small ceiling at client construction. Introduce a provider-neutral `RequestPolicy` in `nh-core::wire`:

```text
max_output_tokens
response_contract = text | json_object | json_schema(handle)
tool_policy = none | selected(names) | auto
parallel_tool_calls = deny | read_only | allow
stream = false | true
verbosity = terse | normal
```

The RouteResolver clamps requested values to catalog-declared capabilities and route output limits, returning an effective policy and downgrade reasons. Both adapters serialize only supported fields. Unsupported strict requirements fail before spend; optional preferences degrade with a receipt. Structured output should be used first for route classification, context summaries, and fleet decomposition, with local schema validation and at most one repair turn **[VERIFY-LIVE]**.

**Smallest MVP.** Implement `max_output_tokens` on both wires and `json_object` only for live-proven routes; add a golden request-body test per wire.

**THE LAW fit.** One normalized seam prevents provider branches throughout CLI/TUI/fleet. Output caps directly serve smallness, safety, and cost control.

**Judgment.** In scope. **Value: High. Effort: M.** Structured-output field names/support **[VERIFY-LIVE]**.

### A3. Harden tool-call ingestion before chasing more autonomy

**Design sketch.** The present non-streaming parser accepts parallel tool calls and executes them sequentially, but it lacks an explicit call budget, duplicate-ID defense, schema validation, or provider-specific fragment assembly. Add a wire-level `ToolCallAssembler` that enforces unique IDs, known tool names, JSON depth/byte limits, and arguments conforming to the local schema before execution. If streaming is later enabled, the same assembler consumes deltas and finalizes exactly once. Execute mutations serially. Parallelize only tools locally classified as read-only, never merely because a remote server claims they are. Record `malformed`, `duplicate`, `unknown`, `denied`, and `executed` outcomes. MiMo streamed argument and parallel-call behavior needs adversarial live fixtures **[VERIFY-LIVE]**; the same applies to Kimi and DeepSeek tool-call edge cases **[VERIFY-LIVE]**.

**Smallest MVP.** Local schema/size/ID validation plus a per-turn and per-task tool-call ceiling; keep transport non-streaming until the assembler is green.

**THE LAW fit.** Safe and readable. It avoids a provider-specific parser zoo and limits retry/token loops.

**Judgment.** In scope. **Value: High. Effort: M.** Provider streaming shapes **[VERIFY-LIVE]**.

### A7. Batch APIs and speculative decoding: adopt only where the economics survive complexity

**Design sketch.** Provider-native batch endpoints may reduce monetary cost but often introduce a different job envelope, file upload, polling, cancellation, and delayed errors **[VERIFY-LIVE]**. ### A8. Make modality capabilities executable

**Design sketch.** Replace `ChatMessage.content: Option<String>` at the normalized seam with `Vec<ContentPart>`: text, local image handle, remote image URL, video handle, and audio handle. Adapters map only supported parts. The RouteResolver rejects a route missing any required modality before reading a key. Local media is size-checked, MIME-sniffed, hashed, and referenced by handle in receipts; raw binary never enters JSONL. Remote URLs are external input and inherit taint. Add profile knobs for image detail, maximum pixels/bytes, video frame sampling, and audio transcript preference **[VERIFY-LIVE]**.

**Smallest MVP.** Text plus one local-image content part, one keyed Kimi fixture, and route rejection on text-only routes. Video/audio remain handles until schemas are verified.

**THE LAW fit.** Modular and auditable; avoids provider-specific message types and token-bomb base64 in receipts.

**Judgment.** In scope, likely M5/M6 boundary. **Value: High. Effort: M.** Provider schemas/token accounting **[VERIFY-LIVE]**.

## 4. Lens C — token economy and first-class profiles

### C1. Define profiles as desired policy, capabilities as route data

**Design sketch.** Keep `catalog.toml` authoritative for what a route supports and what it costs. Add a small root `profiles.toml` for shipped policy and user overrides in `~/.nosis/profiles.toml`; repository-local profiles may define names but may not auto-activate or raise a user budget. Parse both in `nh-routes`, and have the RouteResolver return an `EffectiveExecutionPolicy` after clamping profile wishes to route requirements.

```toml
[profiles.frugal]
route_strategy = "lowest_expected_cost"
thinking = "minimum_capable"
max_output_tokens = 2048
context_soft_fraction = 0.55
tool_surface = "task"
tool_result_chars = 6000
constitution = "dedupe"
retry_limit = 1
defer_if_savings_pct = 20

[profiles.balanced]
route_strategy = "best_value"
thinking = "task"
max_output_tokens = 8192
context_soft_fraction = 0.70
tool_surface = "task_plus_discovery"
tool_result_chars = 12000
constitution = "full"
retry_limit = 2

[profiles.max-quality]
route_strategy = "quality_first_with_budget"
thinking = "highest_supported"
max_output_tokens = 32768
context_soft_fraction = 0.82
tool_surface = "all_allowed"
tool_result_chars = 24000
constitution = "full"
retry_limit = 2

[profiles.frugal.provider.kimi]
thinking = "route_required"
```

`preserve_reasoning`, law, sandbox, secret policy, modality, and mandatory approvals are not profile knobs. A profile may lower cost/authority, never falsify a route capability or weaken security.

**Smallest MVP.** Three built-in profiles, output cap + thinking + context threshold + retry limit, one global active profile; provider overrides can parse now and affect behavior after live tests.

**THE LAW fit.** Data-driven, one policy object, no scattered booleans. The number of knobs is a tension; expose five in MVP and keep the rest documented but inactive.

**Judgment.** In scope. **Value: High. Effort: M.**

### C2. Make the profile toggle obvious and cache-aware

**Design sketch.** Add `--profile` to `run`, `chat`, `tui`, and fleet task defaults; add `/profile`, `/profile <name>`, and `/profile show`. The header becomes `route · profile · effort`; the HUD shows the binding constraints (`out≤2k`, `tools:task`, `defer≥20%`). Changing a profile first displays the effective delta. If it changes prompt/tool bytes, say `context kept · cache epoch resets`; if it changes only output/reasoning caps, do not claim a cache reset. Persist per-provider preferences only through an explicit user command such as `nh profile set kimi frugal`; never from a repository checkout.

**Smallest MVP.** Session-wide toggle and `/profile show`; no persistence and no per-provider command until the effective-policy receipt is stable.

**THE LAW fit.** Self-teaching and auditable. Avoids a settings screen.

**Judgment.** In scope. **Value: High. Effort: S–M.**

### C3. Budget money before dispatch, not tokens after the fact

**Design sketch.** Add `CostQuote` and `BudgetReservation` to the route decision. At request start, snapshot price/confidence/clock state. Estimate worst case as:

```text
(known_cached_input × hit_rate)
+ (remaining_input × miss_rate)
+ (max_output_tokens × output_rate)
+ fixed tool fees
```

If cached usage is unavailable, treat input as miss for the ceiling and mark it conservative. Never silently sum different currencies; show separate subtotals unless the user supplies a dated fixed conversion. Fleet reserves worst-case spend for each active task before dispatch so concurrency cannot oversubscribe the budget. Release unused reservation after usage arrives. Stale or unverified prices produce `unknown`/`stale`, not false precision.

**Smallest MVP.** Per-turn cost receipt and a session cap in route currency; fleet monetary reservation follows.

**THE LAW fit.** Honest, safe, and auditable. Currency conversion is deliberately excluded from MVP.

**Judgment.** In scope. **Value: High. Effort: M.**

### C4. Slim tool schemas and bound tool outputs

**Design sketch.** MCP can make every request carry dozens of large remote schemas. Add a local `ToolCatalog` with immutable compact metadata and lazy full-schema activation. `frugal` exposes built-ins plus a tiny `tool_search`/`tool_enable` path; `balanced` selects tools deterministically from task terms/server allowlists; `max-quality` exposes all allowed tools. Do not strip schema constraints, only redundant descriptions/examples/titles when explicitly marked safe. Add `ToolResultEnvelope { excerpt, handle, bytes, digest, truncated, provenance }` in `nh-tools/src/output.rs`; full output is read by range through a local handle and is not copied into receipts. Apply it to `read_file`, `exec_shell`, and MCP uniformly.

**Smallest MVP.** Per-server tool allowlists and a universal inline-character cap with head/tail excerpt and digest. Lazy activation comes next.

**THE LAW fit.** Large direct token saving plus prompt-injection/DoS defense. One envelope replaces several ad hoc truncators.

**Judgment.** In scope. **Value: High. Effort: M.**

### C5. Trim prompts only where semantics are provably redundant

**Design sketch.** The full law and project instructions are cheap when cached but catastrophic if semantically over-compressed. Profiles must not ask a model to summarize its own authority. Provide deterministic `full` and `dedupe` renderers in the prompt-composition seam. `dedupe` removes duplicated harness boilerplate, repeated tool-name prose, empty sections, and exact duplicate paragraphs while retaining every source-authored instruction and source label. An optional compact law must be author-supplied alongside the full text and hash-bound to it; stale compact variants fall back to full. Move volatile memory out of the system prefix. Never let `frugal` omit project hard rules.

**Smallest MVP.** Exact-paragraph dedupe and token/byte report; no semantic summarization.

**THE LAW fit.** Secure and harmonic. It rejects unsafe “save tokens at any cost” behavior.

**Judgment.** In scope. **Value: Medium. Effort: S.**

### C6. Route on expected cost per successful task

**Design sketch.** Cheapest sticker price can be more expensive after failures and retries. Maintain a local, versioned evaluation table keyed by route, task class, profile, and harness version: pass rate, median turns, input/output tokens, cache ratio, and latency. The RouteResolver uses static catalog cost until enough local evidence exists, then computes expected cost with a conservative quality penalty. Warm-cache affinity becomes a small, explicit discount; it cannot override missing modality or budget. A route switch must justify its cold-start cost.

**Smallest MVP.** Static expected token shape per task class in profiles plus a visible route score; learned statistics remain advisory until sample counts are adequate.

**THE LAW fit.** Makes “cheapest capable” measurable and avoids a complex online-learning system.

**Judgment.** In scope. **Value: High. Effort: M.**

## 5. Lens D — context enhancement

### D1. Introduce a prompt frame with hard invariants

**Design sketch.** Add a pure context module in `nh-core` first; extract a `nh-context` crate only when another crate needs to construct context independently. Represent the request as:

```text
ImmutablePrefix(identity, law, project instructions)
EpochContext(goal card, prior summary, selected memory)
RecentHistory(messages and complete tool pairs)
ToolSurface(canonical schemas)
BudgetLedger(input estimate, output reserve, tool reserve)
```

The immutable prefix is created once per route/profile epoch and cannot be mutated. Release builds detect a digest mismatch, open a new epoch, and emit a receipt; they do not rely on debug assertions. Route switching creates a new identity prefix but keeps the dynamic history. Memory and retrieval never enter the authority prefix.

**Smallest MVP.** Move current compaction helpers into a `context` module, add frame/epoch digests, and enforce complete tool-call/result pairs.

**THE LAW fit.** One clear ownership boundary; auditable and modular without prematurely adding a crate.

**Judgment.** In scope. **Value: High. Effort: M.**

### D2. Implement the five-stage compaction ladder faithfully

**Design sketch.** Trigger stages against an effective budget that already reserves maximum output and tool schema cost:

1. **Budget reduction:** lower optional output/reasoning, deactivate unused tools, tighten future tool-result caps; do not delete history.
2. **Snip:** replace oversized completed tool results with excerpt + handle + digest while retaining the call/result pair.
3. **Microcompact:** deterministic removal/folding of duplicate status chatter, repeated failures, superseded file excerpts, and empty acknowledgements.
4. **Context collapse:** produce a schema-validated summary of older turns: goal, owner constraints, decisions, files/regions, changes, verification evidence, unresolved errors, approvals/denials, and provenance IDs.
5. **Auto-compact:** start a new context epoch containing immutable prefix, a stable collapse block, protected anchors, and recent history.

The current “drop messages and prepend an elision marker to a recent user turn” is a valid emergency fallback, not the finished engine. Suggested balanced thresholds are policy data and must be calibrated, not canonized.

**Smallest MVP.** Stages 1–3 plus typed events; semantic collapse only after the deterministic stages are measured.

**THE LAW fit.** Progressive, reversible where possible, and easy to audit. Semantic complexity is isolated to one late stage.

**Judgment.** In scope. **Value: High. Effort: L** end-to-end, **M** for stages 1–3.

### D3. Budget the whole request, not only message text

**Smallest MVP.** Count serialized tool schemas/reasoning, reserve effective `max_output_tokens`, and maintain a session correction factor.

**THE LAW fit.** Safe and lightweight; no tokenizer dependency zoo.

## 7. Lens F — security and auditability

### F1. Pin credentials to audiences before reading them

**Design sketch.** Today route and MCP configuration carry both a vault-entry name and a destination URL. Because repository files are untrusted, a malicious checkout could name an existing entry and an attacker origin. Add a user-owned `CredentialBinding` registry under the user Nosis home, managed by `nh key bind`: vault entry, purpose (`provider`, `mcp`, `oauth-client`), allowed HTTPS origins, optional allowed auth origin, and first/last confirmation. Replace `Vault::get(entry)` at network call sites with a broker operation `get_scoped(entry, Audience)`. It validates scheme/host/port before the secret is materialized. Repository config can request a symbolic credential but cannot expand its audience. HTTP is allowed only on explicit loopback. Disable redirects or require same-origin redirect approval.

**Smallest MVP.** Exact-origin binding for provider and MCP API-key calls; fail closed with an actionable bind command.

**THE LAW fit.** Closes a major credential-confusion/exfiltration class in one auditable choke point.

### F2. Never approve a truncation

**Design sketch.** Current display safety truncates long untrusted lines while execution still receives the original action; MCP arguments have an even shorter summary. ### G9. Strengthen the Claude(plan) → Sol(implement) → Opus(gate) loop

**Design sketch.** Keep role separation, small slices, locked contracts, receipts over transcripts, and owner FEEL approval. Add a standard gate receipt:

```text
scope/files and pre-existing work
behavioral invariants
security/egress changes
catalog/live facts and expiry
tests/property/fuzz/live evidence
cost/UX evidence
known environment blocks
rollback/migration
LAW tenet tensions and rejected alternatives
```

Risk-tier the gate: security/credential/sandbox/context-loss changes require adversarial misuse cases; pure UI/data changes do not need heavyweight ceremony. Pre-authorize necessary seam changes in contracts so an implementer does not face a false choice between breaking scope and duplicating logic. The planner must not accept its own implementation; the gate must inspect behavior and evidence, not only file counts.

**Smallest MVP.** One reusable gate-receipt template and risk tiers.

**THE LAW fit.** Auditable and efficient. Prevents both loose scope and ritual bloat.

**Judgment.** In scope process. **Value: High. Effort: S.**

### G10. Expand evaluation around cost per successful task

**Design sketch.** Fill the currently skeletal evaluation plan with a small fixed corpus: tiny edit, test diagnosis, multi-file refactor, tool-recovery, screenshot task, long-context task, injection attempt, secret-path request, fleet overlap, and context-collapse continuation. **Smallest MVP.** Ten local tasks, three profiles, current three keyed providers, and a CSV/JSON report derived from receipts.

### G11. Address Windows and environment failures as typed infrastructure evidence

**Design sketch.** Model antivirus blocks, executable locks, encoding/terminal failures, and network/TLS sandbox denial separately from product failures. Tests that spawn the real binary should preflight executable launch and report `EnvironmentBlocked` without masking genuine regressions. Keep release/debug differences visible. Add a Windows smoke script outside the unit-test core for terminal restore, process-tree kill, restricted token, path casing/reparse points, and native keyring.

**Smallest MVP.** Typed environment-block classification and one Predator/ASUS smoke checklist receipt.

**THE LAW fit.** Honest and auditable; avoids code churn in response to environmental noise.

**Judgment.** In scope process. **Value: Medium–High. Effort: S–M.**

### G12. Technical-debt order of operations

**Design sketch.** Recommended sequence after M4 is safely closed:

1. Credential audience binding, full-fidelity approvals, read/taint policy, local MCP mutation auth.
2. Request output cap and actual cost receipts.
3. RouteRequest/RouteDecision and routing policy data.
4. Profiles MVP.
5. Tool-result envelope and context stages 1–3.
6. Multimodal typed content and live provider fixtures.
7. Semantic collapse/retrieval memory.
8. Delegates and advanced batch/swarm only after the universal seams are stable.

This order fixes security and measurement before increasing autonomy or provider surface.

**Smallest MVP.** Treat the first four as M5 entry gates; move the rest behind measured acceptance criteria.

**THE LAW fit.** Small, safe, and dependency-ordered.

## Closing opinion

Nosis should resist becoming a universal provider SDK. Its strongest product is a narrow, inspectable decision-and-control plane: one resolver, two direct wires, one safe delegate seam, one context engine, one tool authority model, and one audit stream. The immediate opportunity is not “more models.” It is to make the existing claims—cheapest capable routing, cache-first context, calm approvals, honest cost, and constitution-native safety—true at every boundary and visible in evidence. Once those seams are reliable, adding a route becomes mostly data, and every future provider competes on measured cost per successful task rather than on catalog enthusiasm.
